# v1.2.3 减少账号界面的重复工作

针对使用中反馈的流畅性差距，先修正代码中可确认的重复操作。本次没有测量真机 FPS、帧耗时或网页滚动表现，不能承诺达到官方 App 的流畅程度。

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 一个账号的页面加载完成 | 扫描全部账号的 Cookie | 只排队检查该账号 |
| 返回应用后的会话检查 | 一批最多检查 20 个账号 | 每次动画帧回调最多检查一个，重复请求合并，退出前台取消任务 |
| 登录标记变化或切换账号 | 清空侧栏与抽屉并重新创建全部控件 | 按账号 ID 保留控件，只重新绑定变化的账号；搜索变动才调整可见结构 |
| 同一代理下切换或恢复 | 重复调用系统代理接口 | 在串行队列中复用已确认成功的相同配置；失败后失效，后续重新应用 |
| 重复点击正在显示的账号 | 暂停页面、停止加载、重新设置代理后恢复 | 页面和网络配置有效时直接关闭抽屉 |
| 返回配置页后重新读取账号 | 内存中的会话标记先归零，再重新探测 | 保留本进程已知标记，再异步分帧检查；不将标记作为登录凭据持久化 |

测试覆盖 200 个账号的列表复用：首次创建后，单个账号会话变化只重新绑定一个条目；切换选中账号只重新绑定原、新两个条目，不创建新视图。另验证搜索恢复和删除、代理异步完成顺序、失败后的重试，以及会话任务的合并和取消。这些是工作量与正确性测试，不是设备性能基准。

本地验证：`gradlew testDebugUnitTest lintDebug assembleDebug assembleRelease`，75 项测试通过，Lint 为 0 错误、49 条警告，Debug/Release 构建成功。发布前还由 GitHub Actions 执行测试、Lint、构建和签名检查。

当前列表仍一次创建可见匹配账号的全部控件，尚未使用 RecyclerView 的屏幕内条目复用。网页内部脚本、视频解码、手机刷新率与系统调度等因素未在本次调整，仍需在实际手机上定位。多 Profile、Cookie 存储和不同代理切换时的页面清理规则保持原有行为。
